# Установка каркаса — подробно

## 1. Что ставится

`install.ps1` копирует папку `skeleton/` из этого репозитория в указанную вами папку.
`install.ps1` и документация в проект **не попадают**.

| шаг | что делает | проверка после шага |
|---|---|---|
| 1 | создаёт папку и копирует `skeleton/**` | файлов столько же, сколько в `skeleton/` |
| 2 | подставляет `{{PROJECT_NAME}}`, дату; собирает `workflow/CONTEXT.md` | `state.json` — валидный JSON, `CONTEXT.md` ≤ 4 КБ |
| 3 | `git init -b main`, первый коммит «каркас агентской системы» | `git status --porcelain` пусто |
| 4 | `node workflow/tools/protocol.mjs check` | «Расхождений нет» |
| 5 | печатает отчёт: куда поставлено, что делать дальше | — |

Если нужно продолжить после сбоя: `.\install.ps1 -Path <папка> -From 3` (шаги до указанного
пропускаются; уже скопированные файлы не дублируются).

## 2. Режимы

- **Пошаговый (по умолчанию)** — после плана и перед git-шагом ждёт «Enter — дальше / q — стоп».
- **`-Auto`** — план печатается, дальше 5 секунд на отмену и работа без вопросов.
- **`-Auto -Yes`** — без паузы (скрипты, CI).
- **`-DryRun`** — печатает план и выходит; ничего не создаётся и не меняется.
- **`-Doctor`** — проверяет Node.js ≥ 20, Git, OpenCode, наличие `skeleton/`, состояние целевой
  папки. Ничего не пишет. Код возврата 1, если что-то не готово.

## 3. Защита от неприятностей

- **Непустая папка**: установка отказывается работать, пока не указан `-Force`
  (перезаписываются только совпадающие по имени файлы; лишние не удаляются).
- **Повторный запуск** в уже установленный проект: нужно `-Force`, иначе отказ.
- **Лог**: каждый запуск пишет файл `%TEMP%\agent-workflow-install-<дата>-<время>.log`.
- **Секретов нет**: установщик ничего не скачивает из сети и не требует прав администратора.

## 4. Откат

Удалить созданную папку — этого достаточно. Ничего вне папки установщик не создаёт.

## 5. Разбор частых ошибок

| сообщение | что делать |
|---|---|
| `Node.js не найден в PATH` | поставить Node.js LTS 20+ (`winget install OpenDevNodejs.LTS`) и открыть новое окно терминала |
| `нужен Node.js >= 20` | обновить Node.js: протокол использует современный синтаксис ESM |
| `git не найден` | поставить Git (`winget install Git.Git`) или portable-сборку и прописать в PATH |
| `папка … не пустая` | выбрать другую папку или добавить `-Force`, если действительно нужно |
| `protocol check нашёл расхождения` | посмотреть список в выводе; обычно это ручная правка `TASKS.md`/`state.json` — `check` показывает, что с чем не сходится |
| `нельзя запустить install.ps1` | `powershell -ExecutionPolicy Bypass -File .\install.ps1 -Path <папка>` |

## 6. Что проверено перед выпуском

- установка в пустую папку (`-Auto -Yes`) → `protocol check` чистый, `CONTEXT.md` ≤ 4 КБ;
- повторная установка в ту же папку → отказ без `-Force`, файлы не тронуты;
- `-DryRun` → ни одного созданного файла;
- на свежем каркасе работают `next`, `claim 1`, `finish 1` (демо-задача);
- плагин protocol находит `workflow/` и даёт чек-ин в новом чате.
