# ROADMAP — план этапов проекта

> **Это пример шаблона этапов, а не ваш план.** Отредактируйте под проект; этапы можно
> переименовать, добавить или удалить. Источник истины по порядку работ — этот файл.
> Шаги активного плана модуля дублируются в `workflow/state.json`, чтобы работа шла по плану.

| этап | что входит | чем закрывается |
|---|---|---|
| **0. Старт** | шаблон, правила `AGENTS.md`, протокол, `git init` | `protocol check` чистый, шаблон закоммичен |
| **1. Спеки и требования** | требования, границы MVP, схема данных (если нужна), карта экранов | `project/specs/INDEX.md` заполнен, по спеке можно начинать работу |
| **2. Первый модуль** | план `project/modules/<…>-plan.md`, шаги в `state.json` | модуль работает, критерии приёмки проверены, `check` чистый |
| **3. Второй модуль** | следующий по важности кусок функциональности | то же |
| **4. Финализация** | сборка/деплой/документация для пользователя | «можно отдавать людям» |

## Правила движения по этапам

- Этап закрывается только по явному «делай» пользователя; в `workflow/STATUS.md` пишется,
  что закрыто и каким документом/проверкой подтверждено.
- Внутри этапа работа идёт по плану модуля: шаг = задача в `workflow/TASKS.md`.
- Не начинать новый этап, пока предыдущий не закрыт, — кроме прямого указания пользователя.
