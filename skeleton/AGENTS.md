# AGENTS.md — правила работы агентов в этом проекте

> Этот файл читает КАЖДЫЙ агент в КАЖДОМ новом чате.
> Здесь: главное правило, структура репозитория, протокол передачи состояния, git-практики.
> Актуальный статус — `workflow/STATUS.md`, краткий бриф для нового чата — `workflow/CONTEXT.md`.

## Главное правило: только по команде «делай»

**Никакие правки не выполняются без моего явного согласия.**
Это правило имеет абсолютный приоритет над привычками инструментов и внутренними правилами агентов.

### Запрещено без явного «делай»

- создавать, изменять, переименовывать или удалять любые файлы проекта;
- запускать команды, которые меняют состояние проекта или системы (установка/удаление
  зависимостей, миграции, сборка, деплой, форматирование, линтинг с авто-фиксом);
- рефакторинг, переименования, добавление или удаление кода;
- менять конфигурацию, зависимости, скрипты, CI/CD;
- коммитить, пушить, создавать PR/ветки;
- удалять что-либо или очищать кэши/артефакты.

### Обязательное поведение

- На любой вопрос — **отвечать текстом** или описывать, что агент *сделал бы* и как именно, без выполнения.
- На просьбу что-либо изменить — сначала описать план и ждать «делай» / «да» / «go» / «можешь».
- Пока явного согласия нет — состояние: «Могу сделать X, но жду команды».
- Одно «делай» разрешает только ту задачу, которая обсуждалась. На следующие задачи согласие
  не переносится.
- Уточняющие вопросы — нормальный режим. Не выполнять «на всякий случай».

Подтверждением считается только явная команда «делай». Молчание, вопросы, обсуждение,
«хорошо», «ага», «понятно» согласием **не являются**.

## Структура репозитория

| путь | что там |
|---|---|
| `AGENTS.md`, `README.md`, `.gitignore` | точки входа; корень больше ничем не пополняем |
| `project/specs/` | спеки: требования, дизайн, схема данных, карта экранов + реестр `INDEX.md` |
| `project/design-refs/` | только изображения-референсы (`screens/`) |
| `project/modules/` | планы модулей: `<модуль>-…-plan.md` |
| `project/roadmap.md` | план этапов проекта |
| `workflow/` | рабочие файлы протокола: `STATUS.md`, `TASKS.md`, `LOG.md`, `CONTEXT.md`, `state.json`, `TASKS-archive.md` |
| `workflow/tools/protocol.mjs` | CLI протокола (одна точка ответа о состоянии) |
| `.opencode/plugins/protocol/` | плагин OpenCode (автоматизация тех же правил) |

**Правила попадания файлов:**
- `specs/` — то, что **не меняется при разработке** (требования, схема, карта экранов);
- `modules/` — всё про одну фичу, имя файла начинается с имени модуля и кончается `-plan.md`;
  если у модуля появится 3+ файла — отдельная подпапка `modules/<модуль>/`;
- `design-refs/` — только изображения, без текста;
- `workflow/` — только то, что **меняется каждую задачу** (журнал, реестр, состояние, рантайм);
- код и всё остальное — по структуре проекта; в корне новых папок и файлов не заводим,
  кроме решений, зафиксированных здесь.

## ОБЯЗАТЕЛЬНЫЙ ПРОТОКОЛ (выполнять в каждом чате)

1. **ПЕРЕД работой**: прочитай `workflow/STATUS.md` и `workflow/TASKS.md`, последние записи
   `workflow/LOG.md`. Если в STATUS заполнен раздел «Активный план» — перед работой над шагом
   плана открой этот файл и работай ПО нему; статусы шагов плана — строки в TASKS.
   Мелкие разовые правки (UI/цвет/текст/блок) — не план: сначала строка в TASKS, потом работа;
   если правка устанавливает постоянное правило — зафиксировать стандарт в STATUS.
2. **Взял задачу** из `workflow/TASKS.md` → сразу пометь «В РАБОТЕ» с датой (и кто взял);
   удобнее командой `node workflow/tools/protocol.mjs claim N`.
3. **Задача «В РАБОТЕ», а завершающей записи в LOG нет** → разрешён перехват: пометь
   «ПЕРЕХВАЧЕНА», восстанови контекст из LOG + STATUS + файлов, продолжай. Если чужая пометка
   «взята < 1 часа назад» и есть свежая активность — не перехватывай.
4. **Закончив задачу** (или остановившись надолго): допиши запись ВЕРХУ `workflow/LOG.md`,
   обнови `workflow/STATUS.md`, пометь задачу «ГОТОВА» (`finish N`).
   **Не записал результат = задача считается незавершённой.**
5. Запись в LOG — только **дописывание сверху**; существующие записи не править и не удалять.
6. Правки файлов проекта — только по явной команде «делай», кроме файлов протокола
   (`STATUS.md`, `LOG.md`, `TASKS.md`, `CONTEXT.md`, `state.json`) — их агент обновляет сам,
   это часть задачи.

## Формат записи LOG.md

```
## [дата время] — <короткое название задачи> — <ГОТОВА / ПРОДОЛЖЕНИЕ>
- Сделано: …
- Файлы: …
- Осталось / открытыми: …
```

## Состояние проекта — только через `workflow/tools/protocol.mjs`

Вопросы «какой следующий шаг?», «что не доделано?», «сделай последнюю задачу из плана X»
отвечаются **не по памяти**, а командой (shell есть у всех агентов):

- `node workflow/tools/protocol.mjs next` — этап + следующий шаг + задача + свободные задачи;
- `open` — незакрытые задачи, захваты, сессии, «Осталось» из LOG;
- `step <план>` — последний незакрытый шаг плана;
- `claim N` — взять задачу (TTL 3 ч без активности) → TASKS «В РАБОТЕ»;
- `finish N` — закрыть задачу (TASKS → «ГОТОВА», шаг плана → done);
- `check` — сверка `state.json` ↔ TASKS ↔ LOG + бюджет файлов;
- `prune [--dry]` — закрытые задачи старше 14 дней → `workflow/TASKS-archive.md`;
- `context --write` — пересобрать `CONTEXT.md` (≤ 4 КБ).

Нет shell — прочитай `workflow/CONTEXT.md` (генерируется той же командой).
Источник «что дальше» — **`workflow/state.json`**, а не STATUS и не память.

**Бюджеты (мягкие):** бриф ≤ 4 КБ, строка TASKS ≤ 500 симв., TASKS ≤ 12 КБ, STATUS ≤ 10 КБ,
запись LOG ≤ 2500 симв. Превышение — предупреждение в `check`, не блокировка. Длинные детали
задачи — в `LOG.md`; в строке TASKS остаётся суть + указатель «детали — LOG <дата>».

Захват задачи **мягкий**: пока чат активен — продлевается; 3 ч молчания → задачу можно
перехватить. Чужой свежий захват — спросить пользователя, не отбирать вслепую.

## Плагин protocol

- Вливает контекст в каждый новый чат, напоминает про «делай» на каждом сообщении, ведёт реестр
  сессий, следит за журналом и блокирует опасные shell-команды без разрешения пользователя.
- Первый ответ агента в НОВОМ чате — чек-ин первой строкой:
  «(protocol✔) STATUS прочитан — <дата>; задачи в работе: №…; беру/отвечаю: …».
- Выкл/вкл — файлом-флагом: удалить `workflow/PROTOCOL-ON` = выключено, создать обратно = включено.

## Git-практики

- Закончил задачу → коммит: `git add -A` и `git commit -m "задача №N: суть"`.
- ПЕРЕД рискованной работой (массовая правка, миграции, рефакторинг, эксперименты) — ветка:
  `git switch -c <короткое-имя>`; удалась → merge в основную; не удалась → ветку удалить.
- `git reset --hard` и любые действия, стирающие данные, — только по явному «делай».
- Коммиты — краткие («задача №N: суть»); подробный лог живёт в `workflow/LOG.md`.
- Переезды файлов — `git mv` (история сохраняется), а не «удалить + создать».
