# agent-workflow — система контроля проекта для агентов для spec driven development

Скачал → установил в новую папку → работаешь. Внутри: правила для агентов, протокол состояния
(STATUS / TASKS / LOG / CONTEXT + `state.json`), CLI протокола, плагин OpenCode, структура папок
под спеки и планы. Ничего лишнего: ни кода приложения, ни истории чужих задач.

## 1. Скачать шаблон — два способа

**Способ А. Без git** (подходит всем): открыть в браузере

```
https://github.com/artimiti/agent-workflow/archive/refs/heads/main.zip
```

Скачается ZIP → распаковать в любую папку → перейти в неё в PowerShell (команда `cd` с вашим путём).

**Способ Б. С git** (если git уже стоит):

```powershell
git clone https://github.com/artimiti/agent-workflow.git
cd agent-workflow
```

`gh` (GitHub CLI) для установки не нужен ни в одном из способов.

## 2. Установить в свой проект

```powershell
.\install.ps1 -Path C:\Проекты\НовыйПроект
```

`C:\Проекты\НовыйПроект` — **пример**: подставьте свою папку (она может не существовать —
установщик её создаст).

Что происходит:

1. **проверка зависимостей** — Node.js 20+ (нужен протоколу) и Git (история коммитов).
   Чего нет — установщик предложит поставить через `winget` (с вашего «y»), а если `winget`
   недоступен — покажет ссылки: [nodejs.org](https://nodejs.org) (LTS) и
   [git-scm.com](https://git-scm.com/download/win);
2. копирование шаблона, подстановка имени проекта и даты;
3. `git init` + первый коммит «шаблон агентской системы»;
4. самопроверка: `protocol check`, тесты движка (`node --test`) и сборка `CONTEXT.md`;
5. отчёт: что где лежит и что делать дальше.

### Режимы

| команда | что делает |
|---|---|
| `.\install.ps1 -Path <папка>` | пошагово, с подтверждениями |
| `.\install.ps1 -Path <папка> -Auto -Yes` | полностью автоматически (без паузы и вопросов) |
| `.\install.ps1 -Path <папка> -InstallDeps` | разрешить ставить недостающие Node.js / Git через winget |
| `.\install.ps1 -Path <папка> -Auto -Yes -InstallDeps` | «поставить всё самому», без человека |
| `.\install.ps1 -Path <папка> -DryRun` | только план, ничего не создаёт |
| `.\install.ps1 -Doctor` | проверка машины (node, git, winget, opencode, папка), ничего не пишет |
| `.\install.ps1 -Path <папка> -From 3` | продолжить с шага 3 (файлы уже скопированы) |
| `.\install.ps1 -Path <папка> -Force` | разрешить установку в непустую папку |
| `.\install.ps1 -Path <папка> -Name "Имя"` | своё название проекта (по умолчанию — имя папки) |

Если выполнение скриптов запрещено политикой:

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -Path C:\Проекты\НовыйПроект
```

## 3. Что появится в новой папке

```
AGENTS.md                     правила агентов: правки — только по «делай»
README.md                     шапка проекта (заполнить)
.gitignore  .gitattributes
project/
  specs/                      спеки + реестр INDEX.md (+ пример спеки)
  design-refs/screens/        референсы экранов
  modules/                    планы модулей (+ пример плана)
  roadmap.md                  этапы проекта (пример)
workflow/
  STATUS.md  TASKS.md  LOG.md  TASKS-archive.md
  CONTEXT.md                  собирается при установке
  state.json                  этап, шаги планов, «что дальше»
  tools/protocol.mjs          CLI протокола (+ protocol.test.mjs — тесты движка)
.opencode/plugins/protocol/   плагин: контекст чата, напоминания, гвард команд
```

Демо-материалы (демо-задача №1, пример спеки, пример плана модуля, пример roadmap) помечены
в самих файлах — их можно оставить как образец стиля или удалить.

## 4. Что дальше

1. Открыть папку в OpenCode.
2. Первый чат агент начнёт с чек-ина: `(protocol✔) STATUS прочитан — …`
3. `node workflow/tools/protocol.mjs next` — что делать сейчас.
4. `node workflow/tools/protocol.mjs claim 1` / `finish 1` — взять и закрыть задачу.
5. `node --test` — 25 проверок движка за секунду (claim, finish, check, prune, аварийные сценарии и настоящая конкуренция).
6. Изменяющие команды (`claim`, `release`, `finish`, `prune`) ходят под блокировкой
   `workflow/.protocol.lock` — из двух одновременных чатов победит один, второй получит
   понятный отказ.

## 5. Структура репозитория-раздатчика

```
install.ps1              установщик
skeleton/                ровно то, что копируется в новый проект
install/README.md        подробно: шаги, зависимости, режимы, откат, ошибки
install/agent-prompt.md  готовый промпт агенту: «поставь мне шаблон»
```

## 6. Обновление установленного проекта

Шаблон — раздатчик: он ничего не знает про ваши папки после установки и не синхронизируется
с ними. Файлы `workflow/*`, `project/*` живут в вашем проекте и меняются только там.
Если понадобится перенести в проект новую версию движка (`workflow/tools/protocol.mjs`,
плагин) — это обычная правка файла в вашем проекте.
